```bash

```

访问：


```bash

NODE_OPTIONS=--openssl-legacy-provider npm run build
```

## 管理后台部署

管理后台部署到 CloudBase 静态托管。构建后使用 CloudBase CLI 上传构建产物：

```bash
cd clothing-mall-admin
NODE_OPTIONS=--openssl-legacy-provider npm run build
cloudbase hosting deploy dist/ -e cloudbase-d3g1zmq7r388144eb
```

注意：根目录批量部署不要依赖 MCP `uploadFiles`，项目已知它在静态托管根路径上传上不稳定。

## 云函数开发与部署

云函数入口统一为：

```js
exports.main = async (event, context) => {
  // event.action 分发
}
```

修改云函数后，用 CloudBase MCP 部署：

```text
manageFunctions(action=updateFunctionCode, functionName=xxx, functionRootPath=/Users/combo/MyFile/projects/clothing-mall-cloud/cloudfunctions)
```

共享层注意事项：

- 层内容解压到 `/opt/`。
- zip 根目录必须是 `node_modules/层名/`。
- `updateFunctionCode` 不会更新层；层需要单独 `createLayerVersion` + `updateFunctionLayers`。
- `layer-base` 当前稳定，不做无关修改。

## 数据库

当前使用 CloudBase MySQL。数据库操作通过云函数共享层 `layer-base` 的 `db.query` / `db.execute` / `transaction`。

结构变更流程：

1. 先确认云库现状，必要时查 `information_schema`。
2. 在 `docker/db/migration/` 增加迁移脚本。
3. 同步更新 `docker/db/init-sql/` 中的初始化 SQL。
4. 用 CloudBase MCP 执行 DDL。
5. 运行数据库冒烟：

```bash
node qa/release/db-smoke.js
```

注意：当前 CloudBase MySQL 不支持部分 `ADD COLUMN IF NOT EXISTS` 写法，迁移脚本需先查列是否存在再执行。
