## P0 必测流程

### 1. 商品上架到商城展示

验收目标：管理端创建或编辑商品后，商城端能看到正确展示。

检查步骤：

- 在管理后台或小程序管理端创建测试商品。
- 填写名称、价格、分类、主图、相册、简介、详情、场景标签、商品参数。
- 设置 `status = published` 或执行上架。
- 在商城端首页、分类页或商品列表查询到该商品。
- 进入商品详情，确认图片、价格、详情、SKU、尺码开关展示正确。
- 下架商品后，商城端不再展示。

通过标准：

- 商品可创建、可编辑、可上架、可下架。
- `gallery`、`scene_tags`、`goods_params` 不出现 JSON 解析错误。
- 商城端只展示 `published` 商品。

### 2. 商城快递下单与发货

验收目标：用户可购买快递商品，管理端可发货，用户端状态正确变化。

检查步骤：

- 用户从商城端进入商品详情。
- 选择 SKU，加入购物车。
- 进入结算页，选择快递地址。
- 提交订单，完成 mock 支付或支付前状态验证。
- 管理后台或小程序管理端查看订单。
- 填写物流公司和单号并发货。
- 用户端查看订单状态和物流信息入口。
- 用户确认收货。

通过标准：

- 订单状态按 `101 -> 201 -> 301 -> 401/402` 推进。
- 订单商品、金额、收货信息、物流信息一致。
- 优惠券和运费计算不出现负数或异常。

### 3. 商城自提下单、备货、核销

验收目标：自提订单必须经过备货确认后才生成取件码，并只能在已备货状态核销。

检查步骤：

- 用户下单选择 `delivery_type = pickup`。
- 选择门店、填写联系人和手机号。
- 提交并支付。
- 管理端看到订单为 `501 备货中`。
- 点击确认备货。
- 验证订单变为 `505 已备货`，生成 `pickup_code`。
- 使用正确取件码核销。
- 使用错误取件码验证失败路径。

通过标准：

- 状态按 `101 -> 501 -> 505 -> 502` 推进。
- `501` 状态不可直接核销。
- `505` 状态可用正确取件码核销。
- 错误取件码不能核销。

### 4. 优惠券领取、选择与使用

验收目标：优惠券规则不破坏下单金额和首单/生日等限制。

检查步骤：

- 创建通用券，用户领取。
- 下单时进入可用券列表。
- 使用通用券提交订单，确认折扣金额正确。
- 创建兑换券，使用兑换码兑换。
- 创建或发放注册/新人券，验证首单可用、非首单不可用。
- 创建生日券，验证生日窗口内可用、窗口外不可用。
- 验证百分比折扣和最高价单品限制。

通过标准：

- 通用券只能领取。
- 兑换券只能兑换。
- 新人/注册券满足首单限制。
- 生日券按 `type=4` 规则生效。
- 折扣金额不超过商品金额。

### 5. 订单退款与售后

验收目标：用户退款/售后申请后，管理端能审核并完成处理。

检查步骤：

- 用户对可退款订单提交退款申请。
- 管理端查看退款中订单。
- 同意退款，验证订单和优惠券状态回退。
- 再创建一条售后申请。
- 管理端审核通过或拒绝。
- 换货场景填写物流并完成。

通过标准：

- 退款中状态只允许管理端处理。
- 同意退款后优惠券可回退为可用。
- 售后状态按申请、审核、发货、完成或拒绝推进。

## P1 建议流程

- 管理后台登录、退出、权限不足提示。
- 小程序管理入口权限：普通用户不可访问，管理员可访问。
- 首页活动位优先级：节日商品、特价商品、本周上新。
- 特价商品设置与取消。
- 节日活动创建、启用、关联商品。
- 场景/穿搭内容创建、启用、商城展示。
- 企业微信推送配置可保存，实际发送按测试账号验证。
- 埋点上报和行为分析页面基础数据。
